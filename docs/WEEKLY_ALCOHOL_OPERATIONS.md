# アルコール情報の週次更新（2026年10月31日改修）

この文書はStage3後の更新処理・絞り込みの運用を記録する。既存8画面、待ち時間収集、採用予測モデル、管理者の権限制限は維持する。実運転の日時・Actions URL・保存前後の比較は今回の検証レポートに記録する。

## 接続停止の調査と修正

従来の長い説明・URLを含むUser-Agentでは、DNS・TCP接続・TLS検証が完了しても本文が返らず、robotsと使用条件の取得がタイムアウトした。同じ識別名を短い標準形式 `DisneyCrowdAI/3.1` にした実際の通信は正常に応答した。原因はUser-Agentの形式に依存する応答停止まで確認できた。提供元の内部ルールや文字数制限は確認できていない。

専用の `official_source.py` に通信を分離した。ブラウザー、検索エンジン、人の識別子への偽装、プロキシ、認証・購入ページへのアクセスは使わない。新しい依存ライブラリーや有料サービスは追加しない。

## 公式情報へのアクセス条件

毎回、[robots.txt](https://www.tokyodisneyresort.jp/robots.txt) → [法的制約と使用条件](https://www.tokyodisneyresort.jp/legal.html) → 両パークの提供店舗一覧 → 各店舗メニュー、の順で取得する。robotsが取得できない場合やメニューが許可されない場合は停止する。現在の禁止対象 `/iframe/`・`/app/` は取得対象に含めない。未対応のAllow・ワイルドカード規則が追加された場合も再確認のため停止する。

使用条件の主要本文を正規化したSHA-256と確認範囲を `data/official-source-policy.json` に記録する。本文の変更・設定の欠落・想定外のHTMLを検出したら、商品を更新せず手動確認へ戻す。変更時に自動で新しいハッシュを承認しない。robotsの許可とコンテンツの再利用許諾は別に扱う。商品名・価格・日付・販売先・公式リンクという最小限の事実を保存し、画像・説明文・HTMLは公開データに保存しない。

要求開始の間隔は2秒以上、1調査100要求以内、接続5秒・読み取り15秒。タイムアウト・接続障害・一時的なサーバーエラーは1回だけ再試行し、3回連続失敗で通信を打ち切る。401・403・429では直ちに以後の通信を停止し、別の接続経路で回避しない。robotsの待機時間指定があれば長い方を守る。各要求の対象パス・時刻・HTTP状態・受信量・所要秒数と、確認した条件のハッシュを試行記録に保持する。

## 実行・再試行・保存

- 毎週月曜06:00 JSTに通常調査する。GitHubの起動遅延・欠落はあり得る。
- 毎日06:17 JSTに未完了の週を再確認する。同じ週の最新の自動試行が成功なら公式サイトへの要求は0回で終了する。成功後に強制再確認が失敗した場合は再び再確認対象となる。
- GitHub Actions → Update official alcohol menu facts → Run workflowで手動実行する。通常はforceをオフにし、完了済み週を実際に再取得したい場合だけオンにする。
- 接続の小規模な確認には手動専用のDiagnose official source connectivityを使う。DBを更新せず、robots・使用条件・ランド一覧・最初の店舗メニューを確認する。

完全成功時だけ全体の最終成功時刻を更新する。部分失敗・全体失敗の試行と理由は残す。前回の商品・価格履歴・期間・管理者補足を保持し、解析失敗を販売終了とみなさない。商品詳細が確認できない提供店舗は、その状態を表示する。

既存の `crowd-data`、共通の書き込み順序制御、SQLite整合性確認、差分記録・チェックポイント・バックアップを継続する。再確認を見送った場合は `collection_performed=false`、`source_requests_this_attempt=0`、`attempt_finished_at_utc` を残す。元の成功記録にある要求数・最終成功時刻と、今回の見送り時刻を混同しない。

## 画面の絞り込み

「絞り込み」の中にランド／シー／両方を追加した。上部のパーク選択と双方向に同期し、変更先に存在しないエリア・店舗の選択は解除する。「ビールを除く」はオンでビール分類の商品を除外し、オフで再表示する。ビール系カクテルもビール分類なら除外する。他の検索条件と組み合わせられる。

閲覧時は保存済みデータだけを読み、利用者が絞り込みを変更しても公式サイトへ収集アクセスしない。
