# 実測待ち時間：公開投稿と運用

Stage 4。全ユーザーがログイン不要で「実測待ち時間」から投稿する。管理者認証は審査・修正・無効化にだけ必要。投稿は自己申告であり、実際に現地で計測したことを機械的に証明しない。

## 保存先と初期設定

既存と同じGitHub内の専用 `measured-data` ブランチに、独立SQLite `measured.db` と圧縮復元用チェックポイントを保存する。main・crowd-data・両パークDB・アルコールDBには投稿処理から書き込まない。新しい有料サービスは不要。Streamlitサーバーだけが書き込み資格情報を持ち、投稿者にログインを求めない。

所有者の操作が必要：

1. GitHubで対象リポジトリ `sorapanel7533/disney-crowd-ai` だけを選んだfine-grained personal access tokenを作成する。Repository permissionsの **Contents: Read and write** が必要。アカウント全体のトークンは使わない。有効期限を設け、失効前に更新する。
2. Streamlit Community Cloudの対象アプリの **Settings → Secrets** に、既存設定を保持して次のキーを追加する：

```toml
DISNEY_MEASURED_GITHUB_TOKEN = "作成した保存用トークン"
```

トークンをチャット・ソースコード・Git・スクリーンショットに記載しない。CodexのGitHub接続は、公開アプリの実行時資格情報とは別であり、自動転用しない。未設定時は両入力方法を表示するが送信ボタンを無効にし、「保存完了」と表示しない。

管理者は既存の `ADMIN_PASSWORD_SHA256`（パスワードのSHA-256）を同じSecretsに設定する。既存の認証を継続する。パスワードそのものをソースへ書かない。一般ユーザーはこの値を必要としない。

公式説明：[Streamlit Secrets](https://docs.streamlit.io/deploy/streamlit-community-cloud/deploy-your-app/secrets-management)、[アプリ設定](https://docs.streamlit.io/deploy/streamlit-community-cloud/manage-your-app/app-settings)、[GitHub参照の非強制更新](https://docs.github.com/en/rest/git/refs)。

## 投稿の状態

- `draft`：今から並ぶ、乗車未確定。
- `pending`：未審査。未承認を含む「参考集計」には含むが学習から除外。
- `quarantined`：重複候補、極端な値、同じ再開キーからの集中投稿。参考集計・学習とも除外。
- `approved`：管理者承認済み。非テストかつ表示値を照合できる記録のみ推定の学習に使用。
- `invalid`：管理者無効化。原記録・修正前後・理由を履歴に残し、集計から除外。

記録IDで再送を冪等化。同一施設・開始日時・実測分数の一致は別IDでも隔離する。同一匿名キーの1時間5件以降を隔離、30件以降は拒否。全体で1日2000件が上限。匿名キーの変更で個別制限を回避できるため、本人確認や強い不正防止を保証しない。氏名・メール・電話・IP・GPSはアプリの投稿項目として収集しない。ホスティング事業者の通常ログは本アプリの管理外。

ブラウザーを閉じても再開できるよう、256bitの再開キーをURLに保存する。DBには一方向ハッシュだけを保存し、個人情報や生のキーは保存しない。キー付きURLは本人用の再開手段であり共有しない。利用者がURLを保存し忘れた場合の本人確認・復元は行えない。別の端末はキーなしで集計を閲覧できる。

## 表示待ち時間の照合

「今から並ぶ」では既存Queue-Times取得を実行し、開始時点以前の有効観測を保持する。履歴入力では `park + ride_id` が一致し、観測日時と取得日時の双方が開始以前、観測が20分以内、quality valid、営業中の値だけを使う。未来の取得値・現在値・予測による埋め合わせはしない。履歴欠測時だけ現地表示の手入力を許可し、manual-signと区別する。表示値0分の乖離率・比率はnull、乖離分数は保持する。

## 統計とモデル

件数、平均・中央値乖離、割合、標準偏差（母標準偏差）、10/25/75/90パーセンタイル、分布・相対度数・累積分布・散布図・日別変化を計算する。分布の階級は下限以上・次の下限未満（最後は同じ幅）で、空階級も0件とする。

平均、中央値、待ち時間帯、施設、時間帯と曜日、階層縮約の6方式を日付順に比較する。学習には評価日の前に乗車・承認された非テスト記録だけを使う。後日承認した記録を過去に知っていた扱いにしない。

本番表示は階層縮約による暫定統計のみ。最低20件・5日を表示の暫定的な入口とし、精度確立の証拠とは扱わない。80%相当の範囲は過去乖離の10〜90%点であり、将来の予測区間としての被覆率は未検証。データ不足・休止・古い現在値では推定値を表示しない。既存表示待ち時間モデルは `legacy-corrected-v1` のまま。自動で「検証済み」に昇格しない。

毎日05:40 JST予定の `Summarize actual wait submissions` がデータ変更時だけ統計と比較結果を不変モデルIDで保存する。ジョブの起動時刻・長期安定性は実績で別途確認する。旧版を削除しない。投稿DBがないときは何も作らず終了する。失敗時は直前の保存済み統計を保持する。

## 外部保存と同時入力

SQLiteを取得してトランザクション実行→整合性のある単独ファイルへ直列化→blob SHA照合→元treeと親からcommit→非強制の参照更新→再取得して記録内容を照合、の順。別の書き込みで先頭が進むと最大4回、最新DBに同じ意味の操作を適用する。古いDBをforce pushしない。保存応答が不確実な場合、同じ記録IDで確認・再試行する。

各成功commitに全記録・審査履歴・モデルの圧縮チェックポイントを追加する。Git履歴も残す。DBが破損・欠落した場合は空DBとして上書きせず停止する。10MiBを超えたら書き込みを停止し、保存の分割や別の無料DBへの移行を所有者が検討する。毎投稿SQLite全体をGitオブジェクトとして残すため、高頻度・大量投稿向けの無制限DBではない。

復元は保存先から正常な `checkpoints/<sqlite blob SHA>.json.gz` を取得し、新規ファイルにだけ実行する：

```text
python measured_recovery.py checkpoint.json.gz new-recovered.db
```

復元後は件数・整合性・最新commit以降の履歴を照合してから公開する。既存の本番ファイルを削除して試験しない。

## 公開受入試験

1. Secrets設定後、ログインしていない端末Aで動作確認フラグを付けた記録を投稿する。
2. 外部保存と読み戻し後の成功表示・記録IDを確認する。
3. 外部measured-dataのSQLiteと監査履歴に同じIDがあることを確認する。
4. 再開キーを持たない別セッションBで「動作確認用だけ」「未承認を含む参考集計」を選び、件数と乖離統計への反映を確認する。
5. 開始・乗車ボタン、再開URL、直接入力も試す。未審査データが承認済み集計・学習に入らないことを確認する。
6. 管理者だけが試験記録を承認・修正・無効化できることを確認する。試験記録は承認後も本番統計・学習から除外する。

隔離した保存先を使ったテスト成功と、公開サイトでの実取得・実保存成功は別に報告する。架空の待ち時間を現地実測や精度改善の実証として報告しない。
