# 実運転・継続評価の運用手順

採用モデルは `legacy-corrected-v1` のまま。14日という条件だけで精度確立とは判定しない。実運転で未発生の21時台・翌日・長期運転は、テスト結果と区別する。

## データ品質と比較

`data_quality.py` は、UTC観測/取得時刻、JST互換列、取得時点の鮮度20分、稼働状態、0〜300分、一意観測を確認する。営業中0分は有効。休止/閉園・欠測・未来時刻・UTC/JST不一致・未審査外部値は学習用の実測から除外する。

日別・施設別・時間別に15分枠の充足率を出す。分母は当面09:00〜21:00という仮定で、公式営業時間の確認値ではない。経過済み枠と全日48枠を別集計する。終了済みの日に各主要施設で75%以上かつ8時間以上の有効実測がある日を評価準備済みとする。休止が多い日は観測成功でも評価準備済みにならない。旧DBの正の履歴は表示・現行モデル継続の参考用に保全するが、正式な正解・充足率には混ぜない。

`models/registry.json` と2個の凍結ソースで、旧版・採用版・中央値・重み候補のコード/パラメータを固定した。SHA-256不一致は実行を拒否する。任意のパラメータ変更は新しいモデル版を作り、過去版を改変しない。

`continuous_evaluation.py` は毎日の最初の収集で直近2時間、21時台の最初の収集で翌日9〜20時の比較予測を発行する。これは本番UIのモデル選択を変更しない。発行時点より前に観測・取得された検証済み履歴だけを使い、将来の天気実績・価格・誤差を渡さない。同じ施設/発行/対象時間でモデルを比較し、対象時間終了後に15分枠3個以上の実測がある場合に採点する。

MAE/RMSE/Bias（予測−実測）、パーク別、主要/非主要、日別、時刻別、リードタイム別を記録する。候補の採用審査には、充足率を満たす独立評価14日以上、3つの重複しない期間での改善、MAE10%以上改善、比較対象の対応、日単位bootstrapの改善差下限が正、を要求する。基準を満たしても自動変更はしない。30日以上・異なる季節の確認は別途必要。

ロールバックは採用を含むリリースコミットを通常の `git revert` で戻し、CI後にmainへ反映する。DBの過去予測・モデル版は削除しない。候補へ切り替える変更では `model_registry.validate_active(version,evidence)` の審査を通し、UIの予測経路の変更もレビューする。現在は候補への本番切り替え経路を有効にしていない。

## スケジュールと保存

08:07〜21:52 JST、15分間隔のActionsを維持する。`runtime-audit.json` は、Actions APIで観測した起動履歴と予定枠を分ける。未観測枠は失敗したHTTP要求とは呼ばない。遅延の紐付けは直前枠への推定で、GitHubから元の予定時刻が渡されるわけではない。30分の猶予後も起動が見えない枠を `not_observed` とする。最大100件のAPI履歴に基づく窓であり、それ以前の履歴は別途保存して監査する。

`operation_runs` は実行ID・開始/終了・処理結果を保存する。API失敗後も両パークを処理し、次回再試行する。HTTP失敗と後段の予測/保存処理失敗を区別する。実行失敗はActionsも失敗として残す。

既存SQLiteを各回保存する方式は維持する。併せて `journal/YYYY-MM/実行ID-パーク.jsonl.gz` に更新行の差分を不変保存する。観測だけでなく予測の採点や管理入力の確認応答も含む。画像・秘密値は保存しない。Git履歴は削除・圧縮しない。

容量の計測はDBサイズ、最近のDBコミット、Gitオブジェクト統計、差分の圧縮サイズを記録する。SQLite全体を毎回別のGitオブジェクトとして保持する上限試算と、実測のGit増加量を区別する。Gitの差分圧縮を保証値として扱わない。合計20MiBで月別分割の警告、UIの100MiB同期上限より前に移行する。無期限の長期容量を解決した構成とは判定しない。将来は週次/日次SQLiteチェックポイントと差分の読み込みを、実データで検証してから移行する。

## 整合性と復元

1. 起動前に `python backup_recovery.py .data` で整合性を検査する。破損時は直近5世代までのGit上のDBを調べ、正常なものに戻す。破損したバイト列も `recovery/` へgzip保存する。復元可能な正常版がなければ上書きせず停止する。
2. 通常のバックアップはSQLite backup APIを使う。DB単体だけでなく、`git bundle create backup.bundle --all` でcrowd-dataを含む全履歴を保全する。
3. 別フォルダーへ正常チェックポイントを復元し、`utils.connect_db` で追加型移行する。差分は `data_journal.replay(conn,path)` で時系列に適用する。削除処理はない。同一差分の再投入は重複しない。
4. 両DBのintegrity_check、件数、観測キー、モデル発行・採点・管理入力のackを確認する。元のDBや履歴は消さない。

Streamlit再起動では元DBから初期化し、公開crowd-dataのスナップショットをマージする。元行を消さず、モデルの不変予測と採点欄を別に扱う。

## 管理者の安全な設定

秘密値はこのリポジトリ、DB、チャットへ貼り付けない。所有者がStreamlitのManage app → Settings → Secretsで設定する。

- `ADMIN_PASSWORD_SHA256`: 十分長い専用パスワードのSHA-256。平文パスワードは保存しない。例は伏せ字であり、そのまま使用しない。
- `DISNEY_GITHUB_ACTIONS_TOKEN`: 必要な場合のみ設定する。対象をこのリポジトリ1個に限定したFine-grained tokenのActions書き込み権限。DBへの書き込みは既存Actionsの一時GITHUB_TOKENが行う。期限を設定し、漏えい/不要時には失効させる。

パスワードはPowerShellの `Read-Host -AsSecureString` 等で対話入力し、SHA-256だけをSecretsへ保存する。コマンドライン引数やGitへ平文を残さない。設定値の生成・入力は所有者が実施する。

管理者のDPA手入力はローカル保存と同時に `admin_events` の保留キューへ入る。データ管理から「保留入力を永続保存へ送信」を押すと既存の収集ワークフローへ送る。送信成功は保存完了ではない。Actionsが入力を検証・保存し、crowd-dataにコミットされた後、UI同期で `acknowledged` を確認して初めて永続反映済みとする。

追加トークンを設定しない場合、管理画面から先頭の保留入力JSONをダウンロードし、GitHub Actions → Collect park observations → Run workflow → admin_event に貼り付ける。JSONには公開のパーク/施設/売切れ時刻とイベントIDだけを含み、認証情報は含まない。

認証拒否・正しい認証での保存・隔離DB再起動・外部スナップショットへのack保存/復元をテストする。本番の秘密値設定と実管理入力による外部反映は、所有者の設定後に確認する。本番の既存データを削除してテストしない。

## OCR

通常起動・収集・CIにはOCRの重い依存関係を追加しない。別の研究環境でのみ `pip install -r requirements-ocr.txt` を使う。

`ocr_review.image_manifest` でページ題名、日付、パーク、同一ホストの画像URL、画像のaltの日付を確認する。ただしaltに書かれた施設の並びは正解とみなさない。実画像の縦書き見出しと照合する。画像SHA-256・出典・OCRトークン・セル位置・品質を保存する。

`quarantine` は重複を防いで候補を隔離し、正式な待ち時間にしない。`approve` は管理者権限、審査者、独立した転記、日付/施設/数値/画像ハッシュ、取得利用条件の確認が一致したものだけを `verified_external` として受け入れる。高いOCR confidenceだけでは承認しない。O/0、8O/80、ハイフン、日付違い、施設違いは拒否する。

実画像の全体OCRは不安定。小さいセルに分割した40セルの目視転記照合では40一致だが、これは一般的な誤読率の推定ではない。今回の正式学習への追加は0件。出典の案内に画像等の権利の帰属はあるが、大量取得・再利用の明示許諾を確認できていないため、自動大量取得は有効化しない。

## 時刻を待つ確認

- 次の予定枠以降：予定/起動/取得/コミットの時刻、正の待ち時間、営業中0分、鮮度、失敗からの復旧。
- 2026-10-30 21時台：10/31対象の固定版と比較用翌日版。発行UTC/JST、特徴量の締切、保存値、Gitからの復元を確認。21:00ちょうどとは記録しない。
- 2026-10-31 各対象時間終了後：同日の有効実測で採点し、10/30の実測を誤結合しないことを確認。日別指数の評価は翌日以降の収集で確認。
- 充足率を満たす独立14日以上・30日以上：主要/非主要・パーク・時刻・日・リード別に再比較。モデル調整に使った日を独立検証日と呼ばない。

現時点では未来の実運転を確認済みとしない。追加の定期監視サービスや有料契約は導入しない。
